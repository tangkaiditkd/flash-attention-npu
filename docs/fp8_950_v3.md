# Ascend 950 V3 FP8 forward

The FP8 dispatch accepts E4M3FN Q/K/V with Dq=Dk=Dv=128 and returns BF16 O
and FP32 LSE. Q/KV base tiles are 128/256. It shares the existing public entry
points, cache read and FlashDecode scheduling. Backward is unsupported.

The optional FP32 `q_descale`, `k_descale`, `v_descale` tensors all have shape
`[batch, num_kv_heads]`, retaining the Dao FA3 e7a6402 shape and optionality.
The Python entry makes descales contiguous, matching the existing input preparation
style; the host/kernel require contiguous storage and use `batch * num_kv_heads + head`.
No descale strides are passed to the kernel. A missing tensor means one.
Q descale is indexed by the owning KV head.

`fwd_kernel_quant.cpp` binds resources and pipelines QK, Softmax, PV and RescaleO.
`online_softmax_quant.hpp` implements DN no-mask, causal and sliding-window Softmax.
The quantized ND implementation remains available as a fallback specialization.
The shared matmul, RescaleO, host tiler, AICPU metadata and FD combine keep their
nonquantized defaults. FP8 P uses round-to-nearest-even and saturation.

## Numerical state

Score is FP32 QK accumulation multiplied by `softmax_scale * dq * dk`;
softcap follows this scaling. Online max, exp, sum, correction, temporary O and
O accumulation are FP32. The online sum uses the FP32 exponential before FP8
Cast. The active DN path computes exp(score - (max - ln(256))), fusing
the fixed P scale into the exponential. Persistent max and correction use the
true score max. The ND fallback retains exp(score - max) multiplied by 256.
Final O applies `dv` once after normalization. LSE is
`max + log(sumScaled / 256)`; unscaling by the exact power of two before Ln
avoids cancellation from a separate subtraction of `log(256)`.
Completely masked rows return zero O and positive-infinite LSE.

FD uses BF16 normalized, V-descaled partial O and corrected FP32 partial LSE.
It combines in FP32 using the existing stable log-sum-exp scheme. The FP8
combine distributes heads across both Vector subcores, stages each head's BF16
partials with a strided DMA, and uses separate FP32 multiply/add operations.
It writes the already-computed LSE through DMA. Positive
infinite partial LSE denotes an invalid row; its weight is zero, including when
all partials are invalid. DN partial LSE uses a 32-row-aligned split, ND an
8-row-aligned split.

Byte offsets below are per Vector subcore. The kernel computes them once in
`CalcUBufTileInfo()` and passes `UBufTileHelper` to the epilogues.

| P[0], P[1] | 131072, 147712 | 16640 each | Cast through UB-to-L1 copy |

A subcore always owns a physical 64-row P/LocalOut slot; actual output row
counts are passed separately. Tail blocks retain those slots. DN QK splits
valid Q rows at round-up-to-32/2, ND at round-up-to-8/2. PV computes a physical128-row result and RescaleO consumes only the valid
prefix of each subcore's fixed64-row slot. Compact PV M64 was tested on short Q
but showed no meaningful gain; it is not part of the selected implementation.

|---|---:|---:|---:|
| Q | 0 | 16384 | 1 |
| K | 16384 | 32768 | 2 |
| P | 81920 | 32768 | 3 |

L0A/L0B each have two 32 KiB stages. DN QK uses logical Q/KV/D
128x256x128 tiles (physical KQ MMAD 256x128x128). It uses the lower
128 KiB of L0C with M_FIX flag0; PV retains two upper 64 KiB slots at
128/192 KiB with flags2/3. The unused QK flag1 is seeded and drained
symmetrically. ND QK retains 128x128x128 tiles and two lower 64 KiB slots.
PV uses 128x128x256. FP8 K alignment is32 elements. P and V tails are zero.
Paged K and V transfers segment each256-token tile across independently mapped
pages, so page128 still feeds one full DN QK MMAD rather than two half MMADs.

## Flag lifecycle

All cross-core flags use mode 4, with AIC flag `id+16` for the second Vector.

| Flag | Producer | Consumer | Reverse release |
|---|---|---|---|
| 0/1 S | QK PIPE_FIX | Softmax PIPE_V | Softmax releases after last S read |
| 2/3/4 P | Softmax PIPE_MTE3 | PV PIPE_MTE1 | PV releases after L1-to-L0 reads |
| 5 LocalOut | PV PIPE_FIX | RescaleO PIPE_V | RescaleO releases after last LocalOut read |

S/P use two UB buffers independently of three L1 P buffers. MTE3_V flags 2/3
hold UB P until its L1 copy completes. Correction uses the L1 P ring index and
remains live until the corresponding RescaleO. LocalOut has one buffer; flag 5
prevents its next Fixpipe write from overtaking RescaleO. Empty Vector subcores
still complete the paired cross-core handshakes.

ND always materializes all 64 physical state rows, padding invalid score rows
with negative infinity and their P rows with zero. This keeps max/sum stores
and subsequent vector loads at a complete physical-vector boundary on tails.
Only valid rows are consumed by output epilogues.

RescaleO retains the shared FP32 online update and normalization path. It applies
v_descale once before the final BF16 cast or FD partial write. The single
LocalOut slot is released only after its final vector read; the existing
cross-core protocol protects the following PV Fixpipe overwrite.

## DN implementation and performance revision

The quantized epilogue follows the BSA high-precision transposed-S structure:
separate named S/P stages, FP32 max/sum/correction, four independent max and exp
chains, byte-lane FP8 Cast, Gather and eight padded stripes copied to L1. Score
scaling and causal/KV-tail masks now stay in the register traversals; no separate
PrepareDN UB pass remains. Positive scaling is applied after the raw max reduce;
negative scaling is applied before max. The scale-sign predicate is computed
outside VF and passed as a boolean. E4M3FN, P scale 256, the true max and FP32
pre-Cast sum remain the target contract rather than HIF8-specific numerical choices.

The quantized kernel specializes its already-fixed D=128, Q/KV=128/256 and buffer
counts as compile-time constants. UBufTileHelper still owns the shared offsets;
no additional allocator, kernel validation layer or production D2H was added.
QK Fixpipe uses each L0 tile's shape rather than the parent UB origin shape.
The buffer counts and cross-core handoffs remain the resource table above.
See the validation record for measured large-shape DN gains and raw samples.

## Second DN optimization revision

The full256-token DN QK tile follows QFA FP8 IterateBmm1Dn: a single
GM-to-L1 tile and MMAD/Fixpipe replace two128-token operations. The actual
paged copies retain page-table addressing and split at page boundaries.
The BSA HIF8 four-chain FP32 reduction is retained. After adding the scaled
FP32 exponentials to those sums, the P packing phase recycles dead exp
registers for byte-lane Cast/Or/Gather and uses a post-increment strided Store.
The max and exp/P loops retain four independent register chains, including
short KV tails; invalid score lanes are masked and produce zero P. The fixed physical P
slots, L1 layout and paired subcore synchronization remain unchanged.

Exploratory P1/LocalOut2, Q residency in L0, eight-exp unrolling and exponent
bias conversion were measured and rejected. None changes the final resource
budget or numerical contract. Experiment inputs, failures and measured
results are retained in the independent tool at perf_dn/opt2/iterations.md.

## Window and short-query revision

Sliding windows now use the same full256 DN QK and FP32 online state. A fully
visible tile reuses the unmasked VF. Boundary tiles use the unsigned interval
predicate `uint32(qCenter + right - key) <= left + right`; this is equivalent
to both signed window comparisons for the normalized nonnegative widths.
GQA query indices are mapped to their logical sequence positions before masking.
Right-window normalization uses the maximum Q length, and left uses KV length,
matching the local Dao host contract even when Q is longer than KV.

PV rounds a tail's K up to the FP8 C0 width32. Its L1 V initialization covers
only the padded K rows in each zN stripe, following QFA's padding-only pattern.
It never clears valid V concurrently with the GM-to-L1 DMA. Page128 transfers
are segmented; page256/512/1024 keep their existing page-table semantics.

The official build recompiles all affected950V3 dispatch translation units.
Partial FP8-only recompilation after shared-template changes is not used for
acceptance, because mixed definitions can invalidate both numerical and timing
results. The final validation report identifies the exact source/binary hashes.

For a window boundary, the scalar wrapper determines the logical query span
owned by the subcore, including modulo/wrap across merged GQA heads. When all
visible K lie within a fixed 64/128/192-column stripe, a compile-time
`KvRange` specialization skips the inactive max, exp and P conversion work. Its P bytes and sum chains remain zero;
the physical P stripes, four-chain FP32 reduction order, online state and all
buffer/flag lifetimes are unchanged. The full-range specialization retains the
four independent instruction chains. There is no per-column scalar branch.
